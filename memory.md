## Design Decisions
- **Colors**: `design.md` contains two color systems (YAML frontmatter M3 export vs. prose named palette) that don't fully agree. Resolved: prose is authoritative for the 5 brand colors (background `#F7F7F3`, near-black `#111111`, Electric Blue `#4D7CFE`, Acid Lime `#C8F31D`, Soft Coral `#FF6B5E`); frontmatter used only to fill gaps prose doesn't cover (error color). Full reasoning: [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) §1.1.
- **Typography**: Single family, Geist, for display and body. Full type scale taken directly from `design.md` frontmatter (no ambiguity there). Display sizes intentionally allowed to clip viewport per prose "Display Rules."
- **Spacing**: `margin-page` 4rem desktop / 1rem mobile, `gutter` 1.5rem, `stack-xl` 8rem, `stack-lg` 4rem, `stack-md` 2rem — all direct from `design.md`. Micro-scale (space-1..6, under 32px) was derived, not in source — documented in DESIGN_SYSTEM.md §1.7.
- **Components**: No component invented beyond what `design.md` specifies or the IA in `scope.md` structurally implies. Work/Experience are list rows with hairline dividers + arrow-up-right hover (not cards) — this was a deliberate reading of `design.md`'s "Lists" component spec, not an assumption.
- **Icons**: Lucide, 2px stroke, sharp joins — explicitly named in `design.md`.
- **Animation**: No library. `design.md`'s only named motions are a 2px hover translate on list-row arrows and hover color-fills on buttons — both pure CSS.
- **Responsive**: Mobile collapses 12-col → 4-col grid, 1rem margins, display-xl scaled down. Exact breakpoint pixel values (640/768/1024/1280) were derived (standard Tailwind scale), not in `design.md` — documented gap.
- **Shadows**: Deliberately absent. `design.md` explicitly states depth comes from borders/layering, never shadows/blurs.

## Development Decisions
- No raw hex/px values in components — everything must reference a token from [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) Part 2. Enforced via `.cursor/rules/design.mdc`.
- Data (projects/skills/experience) must never be hardcoded inside section components — always imported from `src/data/`.
- Server Components are the default; a component becomes a Client Component only when it genuinely needs interactivity.

### Keyboard Shortcuts (documented per project rule)
```
G H → Home / Hero
G P → Projects (Work)
G S → Skills
G C → Contact
?   → Open keyboard shortcuts help dialog
Esc → Close dialog/mobile menu
```
Rules: two-key sequences (press `G` then the letter within a short window), never active while focus is in an input/textarea/select, no effect at all on mobile/touch (no touch equivalent needed — mouse/tap navigation always works identically), every shortcut has a visible non-keyboard equivalent (nav links), does not shadow any browser/OS shortcut.

### Accessibility Rules
- WCAG 2.1 AA minimum. Contrast pre-verified for near-black text (`#111111`) on Acid Lime fill (~14.8:1, passes AAA) — documented because `design.md` didn't specify on-lime text color; white-on-lime is prohibited (fails contrast).
- Visible focus ring always: 2px solid Electric Blue, 2px offset.
- Single `h1` (Hero), correct heading outline regardless of visual type-scale used.
- `prefers-reduced-motion` respected (disables the 2px hover translate / any transition beyond opacity).

### Performance Rules
- Lighthouse mobile Performance ≥ 95.
- `next/font` self-hosted Geist, no external font request.
- No animation library shipped (kept motion to CSS transitions specifically to protect this budget).
